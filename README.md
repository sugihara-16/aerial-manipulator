# A-MSRR 学習を使わない構造と動作の自律生成

**構造選択の根拠を備えた新方式で、未使用120条件中98件成功（81.67%）を確認しました。今回の構造探索・シミュレーション評価の完了条件を満たしています。** 必要な接触・制御余裕を満たすことを条件に、機体自身の重量を含む推力負担を小さくします。全工程で10ms以内に制御計算を終える条件は未達で、VIM4・実機での実行は未検証です。

選ばなかった構造については、台数ごとの重量から得られる負担の下限と、独立した探索の結果を使います。除外できない台数は各99試行を完了し、「その台数について、同じ生成・改善手続きを追加で1回行って、よりよい成立候補を得る確率は5%以下」という根拠を付けます。これは1タスクの全8台数について同時に95%の信頼水準で述べる上限であり、120タスク全体を合わせた95%保証ではありません。**よりよい未探索構造が存在しないという保証でもありません。** この意味での根拠をユーザーは10/22に承認しました。99回という数は `(1 - 0.05)^99 <= 0.05 / 8` から決まります。生成規則を事前に固定し、台数ごとに割り当てた99個の独立試行を完了したことが前提です。速く終わった試行だけを数えたり、未完了を失敗へ置き換えたりしません。

今回選択された構造は2〜6機、番号の付け替えを除く接続骨格7種類、接続口・把持面を含む37種類です。73件で共通初期候補より推力負担が改善しました。構造を返した119件すべてに台数ごとの選択根拠があり、選択未完了の1件は失敗として数えています。全工程の成功例は2〜5機で、分岐を持つ構造4件とpitch把持を含みます。[構造例の画像](artifacts/runs/resumed_holdout120_gallery_20261022/structures.jpg) / [構造集計](artifacts/runs/resumed_holdout120_20261022/structure_report.json)

## 現在の方式

1. 台数ごとに合法な接続関係・接続口・把持面を生成し、物体から接触位置と姿勢を計算します。1〜8機、利用可能な全把持面数、yaw・pitchを含みます。4出発点の生成・改善を1試行とし、共通の物理条件を通過した候補の推力負担を比較します。保持だけでなく、予定した持上げ・搬送の加速と減速に必要な力が出せることも確認し、必要な場合は推力方向の関節角を連続的に修正します。完成構造カタログと全工程の試行結果は選択に使いません。
2. 完成構造をスポーンし、物体へ接近・接触します。取得後の観測姿勢から、摩擦による微小な滑りも含めて保持姿勢とモータ指令を計算します。計算中も取得制御を続けます。
3. 把持後は、機体と物体を合わせた運動量から全体の補正を作ります。ローター・関節の上限内で、把持を崩す内部作用を小さくするよう入力を配分します。持上げ準備などで補正が上限を超える場合は、支持入力を保ち、補正の方向を変えずに出せる最大量まで縮めます。その時点で出せる力と停止距離を使い、経路上の加速・減速を決めます。接触の未来を毎周期シミュレーションする処理は使いません。
4. 支持台へ配置し、機体だけを支える入力へ移します。姿勢を保ちながら退避経路を計算し、その経路で離れます。

**全タスクをシミュレーションで試し、成功した候補を採用する処理は主経路にありません。** 構造と指令を物理条件から生成し、MuJoCoで一連の動作を独立に評価します。シミュレータだけが知る接触力は制御へ渡しません。

全体の力・モーメントが合っても、各パッドの保持は保証されません。保持基準は局所的な近似条件、入力配分はその時点の力学条件です。加速・減速と誤差補正の余裕も固定した姿勢での条件であり、運動中の接触維持や停止を保証しません。全工程の成立は、実際の関節・接触・形状を含む独立したシミュレーションで検査します。

## 開発用の実行

高速な共通部品計算は、リポジトリの仮想環境で `python -m scripts.build_geometry_kernel`、`python -m scripts.prepare_part_bounds`、`python -m scripts.prepare_material_surfaces` により準備します。共通の部品形状を保存するだけで、タスクごとの完成構造や姿勢は保存・選択しません。入力が変わって保存値が古くなった場合は元の計算へ戻ります。PCでの並列数は測定して選びます。

```bash
env -u LD_PRELOAD PYTHONPATH=/home/leus/amsrr_det/build/body_bounds/python \
  OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  .venv/bin/python -m build.check_local_task \
  --request path/to/request.json --output artifacts/runs/new_run \
  --global-structure-search --structure-workers 32 --minimize-input \
  --generated-feedback --momentum-feedback --finite-slip-preload \
  --bounded-allocation --staged-approach --hybrid-withdrawal \
  --background-withdrawal --hold-withdrawal-pose --process-withdrawal --preload-floor \
  --distance-closing --condensed-solve --governed-motion
```

タスク入力には物体形状、初期姿勢、配置先などを記述します。出力先は未使用のディレクトリを指定します。生成構造、全工程の成否、物理監査、計算時間、開始時のソースと設定を保存します。保存構造の再生は開発診断用です。

- 学習器、ケース名による例外処理、完成構造カタログは使いません。
- 機体のトルク・推力・速度、接触力、摩擦、成功条件は維持します。
- 全物理刻みで全形状・荷重・関節等を独立監査します。入力飽和は記録し、非飽和を前提とする説明を飽和区間へ適用しません。
- 本家 `/home/leus/amsrr` は変更・実行しません。必要なコピーは出所とハッシュを記録します。
