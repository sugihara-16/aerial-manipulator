# A-MSRR 学習を使わない構造と動作の自律生成

**タスクの物理要求から、接続構造そのものを作る処理を追加しました。** 「物体をどう支える必要があるか → どこに接触するか → そこへ届くには、どの機体をどの口へつなぐか」という順で生成します。生成後の物理検査と把持運搬制御も維持しています。

現在の既定は、新方式100%です。主探索は台数ごとに固定した独立試行を行い、補助探索は1〜8機を巡回し、各候補に主探索と同じ生成規則を適用して最初の成立候補を返します。両者は同じ姿勢調整・物理検査に通します。1〜8機、yaw・pitchの接続、1接触役割に1機と中継機を扱います。旧生成器が含んだ全自由把持面の組合せを網羅するとは主張しません。部品計算を再利用し、同じ計画中に入力が完全一致した接続評価・姿勢計算・物理検査も共有します。乱数による独立試行はそのまま行い、タスク間で完成構造カタログを保存しません。

2点把持も接触位置を物体表面上で動かします。2点を結ぶ方向に両側から摩擦の範囲内で押し合える条件と、初期の法線間の対向角度を保つ条件を加えます。把持方向の回転や、面上での接触位置の変更は許します。この条件だけで重力支持や全工程の安定性を保証せず、従来と同じ全身・実接触・実行の検査を行います。

理論の土台は、**物体に必要な力・モーメントの釣合いと摩擦条件、および接続口から先の位置を計算する運動学**です。保持と加減速のすべてで同じ接触配置を用います。位置・面の向き・干渉の誤差を減らす接続を優先するため、タスクの抽象化が構造生成へ作用します。途中で一時的に誤差が増える中継も許し、粗い関節角の探索で見つからないことを不可能とは判定しません。

生成した接続関係・接続口・把持面に加え、タスクから導いた接触位置と関節姿勢も、連続的な姿勢調整の初期値へ渡します。接触位置は物体表面上で引き続き動かせます。離散構造だけの寄与を調べる過去の対照実験では、初期姿勢を共通化していました。生成時の力配分が完成姿勢へ保存される保証はありません。候補の受理は後段の物理検査、動作の成立は独立したシミュレーションで確認します。要求作用を使う把持生成の背景は[Lin & Sunの一次資料](https://digitalcommons.usf.edu/esb_facpub/79/)を参照。本方式の飛行機体・速度・成功率を保証する資料ではありません。

## 現在の方式

1. 保持・持上げ・搬送に必要な力とモーメントを、物体の質量・形状・移動から求めます。摩擦とパッド荷重の条件から、共通の接触位置と面の向きを選びます。その配置へ届くよう、実機モデルの接続口・関節運動から接続先と把持面を一つずつ決めます。こうして接続構造自体がタスクに依存します。生成後は共通の姿勢調整と物理検査で候補を受理し、必要な余裕を満たす中で推力負担を比較します。
2. 完成構造をスポーンし、物体へ接近・接触します。物体が接触で動いたら、同じ把持形状の目標を物体へ追従させます。指令変更の影響は、パッド・支持台・関節駆動を含む同じ1周期の式で見積もります。取得後の観測姿勢から、摩擦による微小な滑りも含めて保持姿勢とモータ指令を計算します。計算中も取得制御を続けます。
3. 把持後は、機体と物体を合わせた運動量から全体の補正を作ります。現在の姿勢で基準指令が生む力と重力を計算し、設計した作用との差も補償します。持上げ準備で意図した入力移行は維持します。モータ上限と計算上の接触条件を満たす範囲で、内部の加速度を変えすぎないよう入力を配分し、必要なら全体作用を実現可能な値へ調整します。経路上の加減速も、その時点の駆動能力と停止距離を使って決めます。未来の接触を毎周期シミュレーションする処理は使いません。
4. 支持台へ配置し、機体だけを支える入力へ移します。姿勢を保ちながら退避経路を計算し、その経路で離れます。

**全タスクをシミュレーションで試し、成功した候補を採用する処理は主経路にありません。** 構造と指令を物理条件から生成し、MuJoCoで一連の動作を独立に評価します。シミュレータだけが知る接触力は制御へ渡しません。

全体の力・モーメントが合っても、各パッドの保持は保証されません。保持基準は局所的な近似条件、入力配分はその時点の力学条件です。加速・減速と誤差補正の余裕も固定した姿勢での条件であり、運動中の接触維持や停止を保証しません。全工程の成立は、実際の関節・接触・形状を含む独立したシミュレーションで検査します。

## 開発用の実行

高速な共通部品計算は、リポジトリの仮想環境で `python -m scripts.build_geometry_kernel`、`python -m scripts.prepare_part_bounds`、`python -m scripts.prepare_material_surfaces` により準備します。共通の部品形状を保存するだけで、タスクごとの完成構造や姿勢は保存・選択しません。入力が変わって保存値が古くなった場合は元の計算へ戻ります。PCでの並列数は測定して選びます。

```bash
env -u LD_PRELOAD PYTHONPATH=/home/leus/amsrr_det/build/body_bounds/python \
  OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  .venv/bin/python -m build.check_local_task \
  --request path/to/request.json --output artifacts/runs/new_run \
  --global-structure-search --structure-generator task --structure-workers 32 --minimize-input --steps 80 \
  --generated-feedback --momentum-feedback --finite-slip-preload \
  --bounded-allocation --staged-approach --hybrid-withdrawal \
  --background-withdrawal --hold-withdrawal-pose --process-withdrawal --preload-floor \
  --distance-closing --condensed-solve --governed-motion \
  --observed-handoff --nearby-handoff --inertial-input-updates --contact-coupled
```

タスク入力には物体形状、初期姿勢、配置先などを記述します。出力先は未使用のディレクトリを指定します。生成構造、全工程の成否、物理監査、計算時間、開始時のソースと設定を保存します。保存構造の再生は開発診断用です。
