## 手法

構造生成は、**必要な力とモーメント → 接触位置と面 → そこへ届く機体の接続**の順です。物体の質量・形状・移動から要求を作り、接続口と関節の位置計算を使って構造そのものを方向付けます。生成後は共通の姿勢調整と物理検査を行います。主探索は1〜8機を台数別に扱い、補助探索も同じタスク駆動の規則を使います。2点把持の接触位置も、対向関係を保って動かせます。学習器と完成構造カタログは使いません。

構造の比較では、必要な余裕を満たす中で機体自身を含む推力負担を小さくします。重量による下限と、台数別の独立した生成・改善試行の結果を使います。探索をもう1回行って改善候補を得る確率の評価は、未探索に良い構造が存在しない証明とは区別します。生成規則を変えて全合法構造を網羅したとは主張しません。

新制御は、入力を計算する処理と100Hzで指令を出す処理を分けます。

1. 観測した物体の位置・姿勢・速度から、必要な物体の力とモーメントを求めます。機体と物体の相対姿勢、関節姿勢も補正します。把持前は物体との相対位置へ追従しつつ、機体全体が流れる速度を抑えます。荷重を受けるにつれて物体速度への追従を加えます。定常的なずれには、誤差の積み重ねによる補正を加えます。円柱などの回転対称な形状では、形状が変わらない軸回転を機体の把持姿勢で追いかけません。物体の実角速度、目標姿勢への補正、最終姿勢の判定は維持します。
2. 物体への力の目標と、実際に送る関節・ローターの指令を、一つの制約付き計算で配分します。機体の力学、関節トルク・推力上限、摩擦条件を使います。物体の合力・モーメントを変えない押し合いの力だけを取り出し、必要な押付けから過度に外れる配分を不利にします。**計算した接触力は目標値であり、実際に生じた力の予測や成功証明ではありません。** シミュレータの接触力真値は制御へ渡しません。
3. 同じ制御則へ、接近・荷重移行・持上げ・搬送・降下・解放・退避の目標を渡します。解放では物体の重量を台へ移しながら、残っている接触を使って位置・姿勢・速度を整えます。その時の実際の機体姿勢から滑らかに開き、退避距離は物体とパッドの寸法から求めます。別タスクでは、接触役割と目標に加え、対象が自由に動くか、台や関節で運動を制限されるかというモデルも与えます。共通化するのは力・運動の目標を駆動指令へ配分する部分です。接触手順、実際に加わる力の精度、別タスクの成功率は個別の検証が必要です。

接近時の開いた姿勢も、接触面を物体の外側へ動かす幾何計算で生成します。元の開き方より移動の時間尺度が半分以下になり、形状の検査と駆動上限内の空荷保持が成立するときだけ置き換えます。全工程を試して選ぶ処理ではありません。持上げ高さは物体の大きさと姿勢ずれによる最下面の変位から決め、距離が増えた分は時間も延ばして、最大加速度を増やさないようにします。途中の追従やタスク成功を保証する規則ではなく、実行結果を独立に評価します。

入力計算は独立した処理で行い、数値解法は8msを目安に打ち切って実入力上限内の途中候補を返します。指令を出す側は計算終了を待ちません。観測・計算依頼は毎10msに行い、完成した結果は次の観測周期まで待たず、1msごとの受信確認で適用します。結果が遅れれば前の関節サーボ指令と推力を継続し、関節の位置・速度への帰還はその間も物理アクチュエータで働きます。**指令出力時間と、観測から新しい指令が作用するまでの時間を分けて記録します。** 背景計算が10msを超えた記録も保存します。

物理予測を何度も走らせる処理は使いません。計算機の実測遅延を物理時刻へ写し、シミュレーションの積分処理が遅いことを利用して計算結果が早く届いた扱いにしません。通常のOSにおける全状況での締切保証とは区別します。

補助的な接触荷重・一時離脱・距離条件による安全停止は使いません。実モータ上限、非有限の状態、極端な衝突・不安定性は検査します。最終判定は、実際の持上げ・搬送離隔、配置位置・姿勢・速度、全パッドの分離、解放後2秒の経過です。段階が進んだことを成功にはしません。

接触計算にはMuJoCoのnative方式を使います。多面体同士と円柱の平らな端面は複数点で支え、円柱側面には法線が安定した単接触を使います。端面の複数点は、単接触から独立に得た法線と整合する場合だけ採用します。形状と接触面の幾何による共通規則で、タスクIDによる例外処理ではありません。従来の摂動方式では円柱の解放後の加速、一律の単接触方式では平底物体の持続移動を確認したため、法線・自由転動・面支持・刻み感度から選び直しました。材質・機体上限・タスク条件は変えていません。実機の接触応答と同一とは主張しません。[独立検査と採用根拠](artifacts/relative_control_20261028/collision_adoption103.json)に記録しています。
