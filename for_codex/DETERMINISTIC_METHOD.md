# A-MSRR 学習を使わない構造と動作の生成

**歩行Dock面の追加条件を満たしました。** pitch側（female）は接触面を地面へ向け、yaw側（male）は傾きを許可します。生成・制御・実接触の監査へ同じ区別を適用し、固定36条件で33件成功（91.7%）、成功例の歩行平均ホバー代理比37.93%、初期計画最大14.50秒を確認しました。[今回の結果と動画](../artifacts/walking_face_20261109/VALIDATION.md)。

**把持・バルブ・歩行を共通の入力形式とGUIから実行できます。** 条件入力→新規構造生成→物理実行→判定を接続し、完成構造からの開始、離陸・合体からの連続実行、組立のみを選べます。連続実行には未解決の移動失敗例があり、以下の既存全条件成績とは分けて扱います。[共通仕様・起動方法・確認範囲](TASK_FORMAT.md)。

**個別離陸から空中組立、中央制御への切替、安定ホバリングまで実装しました。** 確定した接続構造を保ち、逐次・並行の手順を比較します。全219条件で時間条件込み218件成功（99.5%）、全219件で物理的な組立・保持を完了しました。1件の発行12.53msは失敗へ残し、全周期10ms以内を達成したとは扱いません。組立・最終保持はホバリング確認後最大22.94秒、組立の計画準備は最大6.00秒です。[組立方式](ASSEMBLY_METHOD.md) / [結果と動画](../README.md)。

その後段の歩行は、空中保持→変形→着陸→5mを連続して実行します。組立の成績とは分けて扱い、今回の接地面条件では上記の33/36・37.93%を得ています。

## タスクから構造・動作へ

1. **構造を生成する。** 指定された機体数・速度・曲率と必要な支持荷重から、足の役割、接続口、枝の伸ばし方を決めます。タスクの要求が生成そのものを方向付けます。
2. **歩き方を作る。** 各構造で足を上げる順序、歩幅、関節姿勢、ローターの向きを計算します。実際の慣性・摩擦・関節と推力の上限・形状干渉を検査し、成立する候補の消費負担を比較します。
3. **空中から接続する。** その構造が自由飛行で支えられる姿勢を求め、変形・降下・推力方向の切替を計画します。有限時間の動荷重も検査し、未接触の地面反力は借りません。全工程のシミュレーション成功で候補を選ぶ方式ではありません。
4. **共通制御で実行する。** 同じ制約付き入力配分に工程ごとの姿勢・足・重心目標を与え、関節とローターを動かします。実際の接地状態に応じて支持を利用し、持続する追従誤差を上限付きで補正します。着陸時に物理状態をリセットしません。

今回の接地条件は、pitch側のfemale Dockに限って加えています。生成する支持姿勢では面の傾き1度以内、実際に重量の2%以上を支える接触では5度以内を確認します。yaw側のmale Dockは傾きを許可します。制御は観測した足の位置・向き・速度を使って補正し、地面へ届く前の足に架空の支持力を与えません。実際の接触力は独立した成功判定に使い、制御へ正解として渡しません。

消費の比較は、各脚の支持時間を重みとして静的姿勢へ反映し、その後に一周期の運動と推力方向を整えます。生成の初期向きや制御の追従係数には経験的設定を含みますが、物理上限や成功基準は変更していません。

## 比較の根拠と時間

各タスクで59回の基本生成・改善を完了します。固定手続きから独立に得た59出力という仮定の下では、「同じ基本手続きを追加で1回実行して改善候補を得る確率」の上限は、条件ごとの信頼水準95%で約4.95%です。未探索の良構造の不存在や、実行成功の保証ではありません。

残時間では選択案のローター方向を追加改善します。従来の順次改善と、後段を先に始める改善を並列に比較し、全検査を通り費用が下がったものだけを採用します。この追加処理は独立試行数へ加えず、実行準備とともに初期15秒へ含めます。

指令発行は100Hz。計算が遅れる間も旧指令で物理を進めます。最終版の発行処理は最大5.33ms・10ms超過0、新しい観測が作用するまでの遅延は別に最大17.5msでした。PC上の実測であり、VIM4・実機・OSの厳密な時間保証ではありません。
