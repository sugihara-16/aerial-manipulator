# 共通タスク仕様とGUI

GUIで条件を入力すると、版番号付きのJSON（データを記述するテキスト形式）へ変換し、その同じデータから構造生成・物理実行・判定を行います。保存したJSONはGUIまたはコマンドから再入力できます。構造そのものを入力する形式ではありません。毎回、条件から構造を新しく生成します。

GUIの表示言語は英語です。タスクと実行範囲を選び、`Start`で開始、`Stop`で停止します。

## 起動と操作

リポジトリで次のコマンドを実行すると、専用ウィンドウが開きます。ブラウザやHTTPサーバーは使用しません。

```bash
./scripts/task_gui.sh
```

初回の追加依存は `.venv/bin/python -m pip install -r requirements-gui.txt`。Qt 6.8.3を固定して使います。Ubuntuでは `libxcb-cursor0` も必要です。このPCは設定済みです。`./scripts/install_desktop_entry.sh` でアプリ一覧に **A-MSRR Task Workspace** を登録できます。

3D画面はMuJoCoをOpenGLで直接描画します。左ドラッグで回転、右/中ドラッグで平行移動、ホイールでズーム、ダブルクリックまたはFit viewで全体表示。Follow robotで機体追従を切り替えます。設定と結果のパネルは移動・切り離しが可能です。Recent runsと装飾ヘッダーはありません。

制御は従来の別プロセスで実行し、GUIは公開された姿勢・速度・接続状態を読み取るだけです。画像配信プロセスを起動せず、GUI内で物理を進めません。描画要求は約60Hz、状態/生成図の取得は150ms間隔で、実際の描画速度は計算機と負荷に依存します。StopはそのGUIが起動した実行だけを停止します。実行中にウィンドウを閉じる場合は停止を確認します。

旧ブラウザ版は `./scripts/task_gui.sh --web` で起動します。既定URLは http://127.0.0.1:8765 、変更は `--web --port 8766`。既存サーバーがあればURLを表示して終了し、既存の実行を停止しません。

1. 把持・運搬、バルブ回転、歩行からタスクを選ぶ。
2. 対象の形状・質量・姿勢・移動量、バルブの抵抗と向き、または機体数・歩行速度・曲率を入力する。
3. 実行範囲を選び、スタートする。生成後に実際の物理状態を映像表示する。
4. 成功／不成立、機体数、計画時間、制御時間、判定の内訳を確認する。入力・物理要求・結果・ログを保存できる。

実行範囲は次の3つです。

| 選択 | 実行内容 |
| --- | --- |
| 完成構造からタスク実行 | 新規構造生成→空中配置→タスク。歩行は変形・着陸から開始 |
| 離陸・合体からタスクまで連続実行 | 新規構造生成→地上の個別機体→離陸・合体→開始位置への移動・変形→タスク |
| 構造生成と組立のみ | 選んだタスクの構造を新規生成→個別離陸・合体→安定ホバリングで判定 |

一度に実行するのは1条件です。停止ボタンは、その実行の計算・描画プロセスを終了します。他の作業のプロセスは操作しません。ローカルPCからのみ接続できます。

## 共通の構成

単位はm・kg・s・rad・N・Nm、座標は世界座標です。GUIの角度入力は度ですが、JSON保存時にradへ変換します。

| 項目 | 意味と用途 |
| --- | --- |
| `version` | 仕様の版。現在は1 |
| `task` | `grasp` / `valve` / `walking`。対応する要求変換器を選ぶ |
| `scene` | 重力・地面・対象形状・質量・初期位置姿勢・バルブ抵抗 |
| `robot` | 使用機体の型、台数の探索範囲または固定台数 |
| `contacts` | 接触する部位・相手・許可面・接触数・支持方法 |
| `goal` | 何をどこまで動かすか、速度・経路・解放などの終点要求 |
| `objectives` | 物理的な余裕を満たした上で、推力負担を小さくする比較目的 |
| `acceptance` | タスクを成功と判定する規則の版 |
| `execution` | 実行範囲、初期状態、乱数、計画（歩行20秒、把持/バルブ15秒）・制御10ms・実測遅延、組立期限 |

例は [把持](../configs/tasks/grasp.json)、[バルブ](../configs/tasks/valve.json)、[歩行](../configs/tasks/walking.json)。`requirements.json`には、この仕様から構造生成・制御へ渡した要求と、重力荷重・回転軸・横加速度などの導出量が残ります。

現行版は既存3タスクの対応範囲を厳密に定義します。任意の新しいタスクをJSONだけで追加できる汎用計画器ではありません。未対応の項目・値や、実行器が使えない変更は入力エラーにし、黙って無視しません。例えば機体の変更、斜面、任意障害物、制御周期の変更、上下面を使うバルブ接触は未対応です。指定できる数値範囲はGUIの入力定義と検査で共用しています。入力可能な範囲すべてで成功を保証するものではありません。

## 判定規則

`acceptance.profile` は以下の既存判定を参照します。GUIから閾値を変えて成功扱いにする機能はありません。

- `grasp_v1`: 搬送中10cm以上のクリアランス、目標位置誤差3cm未満・姿勢誤差0.2rad未満、物体速度0.02m/s未満・角速度0.1rad/s未満、把持面から2cm超の離隔、接触終了後2秒以上などを実物理状態で確認。
- `valve_v1`: 左回り180°に対して誤差5°未満、軸速度0.02rad/s未満、解放・静止・退避後の飛行保持、荷重をかける全物理刻みで棒の側面以外を使っていないことを確認。
- `walking_v1`: 指定距離（最低5m）、平均速度・5秒区間速度、経路誤差・姿勢、地面での重量支持、実際の歩幅・離床・支持交代を確認。歩行前の空中保持・着陸も判定。歩行区間のホバー消費比は結果へ記録し、単発の成功条件と、従来パネルの成功例平均40%未満の条件を区別する。
- `assembly_v1`: 全接続・制御引継ぎを終え、各機の位置4cm・姿勢3°・速度0.06m/s・角速度0.1rad/s以内の保持を1秒継続。ホバリング確認後30秒以内。

いずれも推力・トルクの物理上限を維持し、極端な衝突・不安定性を検査します。計画と制御の時間超過も成功から除外します。連続実行では組立・移動・タスクの各工程を分けて記録します。新しい指令を計算している間も旧指令で物理を進め、工程の切替準備にも実測時間を反映します。この間は直前の入力を10msごとに再発行する軽量な保持処理を用い、新しい観測に基づく制御ではないことと、観測更新の空白時間を別記します。物理の数値積分にかかる時間と制御遅延は別であり、壁時計と等速の映像ではありません。

## 実装への経路

```text
GUI入力 / JSON読込
  → 共通仕様の検査
  → scene・resources・contact_domain・motion・objectives・acceptance・stages
  → タスク別の物理モデル・要求へ変換
  → 既存の構造生成
  → 選択した初期工程と共通制御
  → 物理状態の監査と共通結果
```

変換と検査は `amsrr_det/task_spec.py`、実行への接続は `task_execution.py`。把持は採用済みの `build/check_relative_task.py`、バルブ・歩行・組立は既存の `scripts/run_*_task.py` を呼びます。固定指定の接触領域や機体条件は、各実行器の採用済み規則と一致する場合だけ受け付けます。

連続実行では、個別機体の自由運動と接続口の拘束を持つ同じ物理モデル・状態を最後まで使います。制御器への観測だけを必要な関節座標へ写します。合体後に完成体へ置き換えたり、位置・速度・物理時計を初期化したりしません。関節指令の表現を切り替える瞬間は同じ力を維持し、その後の入力差を0.6秒で取り除きます。組立で使う簡略気流モデルは後段も継続します。

合体後の移動では、水平移動と関節変形を同時に進め、固定の追加上昇・区間ごとの停止・3秒待機を行いません。対象物を変形途中の機体が横切らないよう、41時点の形状計算で経路を確認し、必要な場合だけ下降の進行を遅らせます。有限点での検査であり、連続経路全体や実機の安全保証ではありません。歩行の連続実行は着陸用の空中姿勢へ直接移り、重複する保持・変形を省きます。接地に伴う下降と地面への荷重移行は維持します。

描画は別プロセスで、制御が公開した状態のコピーだけを読みます。状態公開は最大60Hz、描画・JPEG連続配信は30fpsを目標とします。状態公開の処理は制御時間に含めます。描画待ちを制御へ入れません。画面の`render fps`は描画側の実測値で、ブラウザ自身の表示速度とは区別します。チェッカー地面と影付き照明は描画専用で、物理条件を変更しません。

GUIを使わない場合:

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 PYTHONPATH=. \
  .venv/bin/python -m scripts.run_task configs/tasks/valve.json artifacts/manual_valve
```

専用GUIの実行結果は `artifacts/desktop_console/<実行ID>/`（旧ブラウザ版は `artifacts/task_console/<実行ID>/`）。共通入力・導出要求・実行器入力・生の判定・共通結果を残します。保存計画を再利用して新規生成扱いにはしません。

## 構造生成の表示

Start後、Structure generationに、探索中の機体数ごとの生成サンプルと検査合格候補を表示します。把持・バルブは探索した台数ごと、歩行は入力した固定台数です。図は全関節角度を0にした二次元の上面図です。接続口の種類と接続関係を維持し、ローター4つ・機体・Dockを描きます。数字は機体番号、橙色のDockは接触役割です。0度配置で機体中心が重なる場合は番号を併記します。実際の計画姿勢やタスクの接触目標はこの図には表示せず、実行時の関節角度は変更しません。

専用GUIは台数ごとに、モデル検査に合格した最良候補があればそれを、なければ最新の生成サンプルを表示します。旧ブラウザ版は両方を別々に表示します。専用GUIは収集済み結果数と合格数を併記し、旧ブラウザ版は不合格数・物理的な下限による除外数も表示します。全生成候補数ではなく、探索側が収集した結果の件数です。把持では独立探索に加え、補助探索から採用可能な結果が返った場合も1件含みます。途中打切りは不合格に数えません。

探索終了から実行開始までは検査合格候補を表示し、最終採用した構造だけを緑枠のSelected for executionにします。実行開始後は候補一覧を隠し、採用構造の二次元図だけをシミュレーション画面左上へ小さく表示します。専用GUIは3D画面へ切り替えます。履歴一覧は表示しません。実行開始前に計画が失敗した場合は候補一覧を残します。検査合格はシミュレーション成功の保証ではありません。合格記録がない台数では最後の生成サンプルをその旨とともに表示します。以前の履歴には検査状態の記録がない場合があります。

旧ブラウザ版の生成表示は50ms間隔（20回/秒目標）の独立した取得処理です。取得中は次を重ねず、全候補の逐次表示ではなく最新のサンプルへ追いつきます。状態の取得は800msです。生成器は既存配置を間引いて公開し、接続構造から関節角度0の図を作る計算はGUIサーバー側で行い、同じ接続構造の結果を再利用します。探索は描画を待たず、表示専用の最適化・物理計算も行いません。GUI以外では表示用の公開処理は無効です。
